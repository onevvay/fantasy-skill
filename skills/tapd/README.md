# TAPD Skill

TAPD 需求、任务、缺陷、迭代、工时、评论和受控缺陷修复流程。

## 安装

```bash
npx skills add onevvay/fantasy-skill --skill tapd
```

## 工作流机制

### 1. 先读缺陷

- 读取完整 TAPD 缺陷 ID、当前状态、标题、描述和必要字段。
- 查询历史评论，避免重复写入固定评论。
- 如果状态为 `重新打开`，必须先完整分页读取并阅读评论。
- 在评论阅读完成前，不得改状态、写评论、改代码或准备修复方案。
- 需要提炼上一轮修复结论、验证结果、本次重开原因和待重新核实的边界。

### 2. 只读定位与复现

读取工作流状态和可达流转，复现问题并记录环境、版本、前置数据、操作步骤、实际结果、期望结果及日志或请求证据。此阶段不修改代码，也不改变 TAPD 状态。

### 3. 修复方案确认

在修改代码、创建提交或为本轮修复写入 TAPD 前，必须先向用户输出方案并等待明确认可。方案至少包含：

- 已确认现象和复现证据
- 已确认或待验证的根因
- 修改模块和实现范围
- 回归测试与真实环境 E2E 方案
- UI 缺陷所需的截图证据方案
- Git 提交信息和 TAPD 回填计划

用户明确要求“直接修复”“跳过方案确认”或“无需等我确认”时，可以跳过本检查点，但不能跳过缺陷读取、重开评论门禁、E2E、截图、状态流转和完整 Bug ID 提交信息要求。

### 4. 接收并修复

方案获认可或明确跳过后，按当前项目工作流流转到 `接受/处理`，核对状态并发布初步 HTML 评论，再实施最小修复和回归测试。

如果创建 Git commit，必须明确标识这是 TAPD 缺陷修复：提交标题以 `fix(tapd):` 开头并包含 `get_bug` 返回的完整 19 位缺陷 ID，正文换行写入对应 TAPD 缺陷链接，例如：

```text
fix(tapd): 修复库存扣减异常 [TAPD-<完整19位缺陷ID>]

TAPD 缺陷：https://www.tapd.cn/<workspace_id>/bugtrace/bugs/view/<完整19位缺陷ID>
```

### 5. 真实验收

在对应 dev/test 环境验证用户触发、接口处理、持久化和展示结果。涉及页面或用户操作的缺陷，还必须提供可访问的截图证据，并绑定完整缺陷 ID、环境、版本、URL、采集时间和操作步骤。

### 6. 评论和状态回填

先发布包含最终根因、修复方案、验证结果、影响面、E2E 和截图证据的 HTML 评论，确认评论已成功并回读，再将缺陷流转到实际可达的 `已解决` 或后续状态。

本地单测、类型检查、构建、Git commit 或 PR 不能单独证明业务验收完成。

## 失败处理

- 强制读取失败、分页不完整、响应不明确或上下文矛盾时立即停止。
- 状态或评论写入失败时先读取确认实际结果，确认未生效且没有重复后最多重试一次。
- 不得猜测状态值、流转路径、REST method 或请求体。
- 不得重复创建固定模板评论。
- 不得把本地截图、构建结果或提交信息冒充 TAPD/E2E 证据。

## 安全约束

Token、密码和密钥只能通过环境变量或客户端私有配置提供，仓库中不得包含真实凭据、本机绝对路径或私有配置文件。
