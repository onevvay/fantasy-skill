## 目录结构

Skill 放在 `skills/<skill-name>/` 目录下。

## 已发布 Skill

- `tapd`：TAPD 需求、任务、缺陷、迭代、工时、评论及受控缺陷修复流程。

安装命令：

```bash
npx skills add onevvay/fantasy-skill --skill tapd
```

## TAPD 工作流

`tapd` skill 使用有门禁的缺陷修复流程，不会把代码修改直接等同于 TAPD 缺陷已解决。

1. **先读取**：读取完整 TAPD 缺陷 ID、当前状态、描述和评论。如果缺陷状态为 `重新打开`，必须先完整分页读取并阅读评论；在此之前不得改状态、写评论、改代码或准备修复。
2. **只读定位**：读取工作流流转规则，复现问题并收集环境、版本、请求、日志和截图证据；此阶段不修改代码，也不改变 TAPD 状态。
3. **方案确认**：输出已确认事实、疑似根因、修改范围、测试方案、E2E 方案、截图证据、提交信息和 TAPD 回填计划，等待用户明确认可后再修复。用户明确说“直接修复”时，可以跳过本门禁，但不能跳过缺陷读取、E2E、截图、状态和完整 ID 提交信息门禁。
4. **接收并修复**：获得认可或明确跳过授权后，按项目工作流流转到 `接受/处理`，发布初步 HTML 评论，再实施最小修复并补回归测试。对应 TAPD 缺陷创建 Git commit 时，提交标题必须包含完整 19 位缺陷 ID。
5. **真实验收**：在对应 dev/test 环境验证原始场景。涉及页面或用户操作的缺陷，还必须提供可访问的截图证据，并绑定缺陷 ID、环境、版本、URL、时间和操作步骤。
6. **凭证回填**：先发布包含根因、方案、影响面、E2E 和截图证据的最终评论，再将缺陷流转到实际可达的已解决或后续状态。写入失败或响应不明确时停止，并先读回核验，禁止盲目重试。

评论使用 HTML 格式，避免重复评论；单测、构建、提交或 PR 不能单独证明业务验收完成。

## 安全约束

- Token、密码和密钥只通过本地环境变量或客户端私有配置提供。
- 仓库内容不包含真实凭据、本机绝对路径或私有配置文件。
- 发布前应检查新增文件中的凭据、路径和敏感信息。
